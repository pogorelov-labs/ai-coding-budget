## Как пользоваться

1. Сначала откройте «Профиль команды»: укажите количество людей в трёх группах и input/output на человека за рабочий день. Сумма групп задаёт размер команды.
2. Создайте отдельный сценарий для каждой альтернативы закупки. Позиции внутри сценария складываются; сценарии не складываются.
3. Добавьте подписку или API и выберите «Вся команда», одну группу или ручной расчёт. В личном плане одно поле «Количество подписок», в командном — «Количество мест». В связанном режиме количество и нагрузка берутся из профиля; вручную количество редактируется непосредственно. Для разных тарифов по активности создайте отдельные позиции.
4. В режиме «Доли моделей» вводится общий вход/выход, доли должны дать 100%. В режиме «Токены по моделям» задаются независимые объёмы каждой модели. Везде единица — миллион токенов.
5. Раскройте параметры строки модели: кеш, запись кеша, TTL, скорость, длинный контекст, геонаценка, ручные цены. У OpenRouter выбирается конкретный хост.
6. В лимитах позиции задайте годовую/квартальную оплату, индивидуальную цену, дополнительную скидку, подтверждённую разовую акцию, перерасход, пакеты и применимые кредиты.
7. Смотрите обычный месяц, первый платёж и прогноз 12 месяцев. Для годового договора первый платёж включает всю годовую предоплату.
8. Сохраняйте JSON для редактирования, CSV для табличного анализа или HTML для автономной копии. Изменения автоматически сохраняются в localStorage этого браузера. Импорт заменяет сценарии текущего браузера. JSON/HTML не синхронизируют данные между сотрудниками.

Профиль общий для всех сценариев. Изменение числа людей или токенов автоматически пересчитывает связанные позиции. Ручные позиции остаются независимыми. В каждой позиции сохраняются свои модели, кеш, скидки и покрытие подпиской. При переходе к явному вводу токенов по моделям включается ручной режим; общий объём сохраняется через взвешенное среднее на человека. Для восстановления отдельных групп выберите профиль заново.

У GLM проверка weekly/5h и доплата выполняются **отдельно по каждой группе**, а затем доплаты складываются. Средний расход команды не используется для переноса лимита от малоактивных к суперактивным. Для OpenAI/Claude один ручной процент покрытия действует на всю выбранную позицию; разные проценты по активности задаются отдельными позициями.

Один разработчик может иметь несколько подписок. Если несколько позиций связаны с полной командой, полный расход профиля учитывается в каждой позиции. Это несколько нагрузок/подписок; распределение одного общего объёма между ними не подразумевается. Для бюджета с разными уровнями подписок выберите конкретные группы в позициях.

Пустая группа (0 человек), если нет дополнительных оплаченных мест, делает связанную позицию неактивной: она не добавляет платежей, бонусов и расхода. Дополнительные неиспользуемые покупки задаются только в раскрываемых настройках. В связанном режиме они добавляются к людям профиля; в ручном входят в указанное общее количество. Токены для них не начисляются.

JSON формата 1 и старый localStorage переносятся в формат 2 без изменения расчётов: их позиции остаются ручными, разница оплаченных/используемых подписок сохраняется в дополнительном параметре. Если старое сохранение содержит невозможную комбинацию «активных больше оплаченных», перенос использует оплаченный счётчик как единое количество. Прежнее число сохраняется в legacyUsers, а в интерфейсе появляется объяснение исправления. Профиль для старого сохранения первоначально относит всех к обычной группе. Кнопка «Подключить профиль к этому сценарию» переводит его ручные позиции на весь профиль; действие можно отменить. Профиль, связи групп и количества входят в JSON и автономный HTML.

## Формулы

Вход `I` уже включает кеш. При доле попаданий `h` и доле записей среди промахов `w`:

```
R = I × h
W = (I − R) × w
U = I − R − W
API = U × input_price + W × write_price + R × read_price + O × output_price
RUB = USD × введённый курс
```

В выход включайте оплачиваемые reasoning tokens. Одинаковое число токенов разных моделей не гарантирует одинаковое качество работы, количество попыток или время выполнения. Batch/Flex имеют другие свойства задержки, чем интерактивное выполнение.

Объём «на человека в день» умножается на активных пользователей и рабочие дни. Месячный объём для проверки квот переводится в среднюю рабочую неделю. Процент длинного контекста — доля токенного объёма в запросах выше порога, а не доля запросов или общий размер проекта.

### GLM

- Используются новые published credits: GLM-5.3 `6.9 / 1.7 / 24`, Flash `2.3 / 0.56 / 8` на 10 тысяч uncached input / cached input / output. При вводе в миллионах коэффициент — 100.
- Пик: будни 06:00–10:00 UTC, то есть 09:00–13:00 МСК. Вне пика расход credits ×0.5. Для равномерного 09–18 МСК средний коэффициент 13/18.
- Недельный и rolling 5h лимиты проверяются на одного активного человека. Модели делят квоту seat; квоты разных людей не объединяются. Считается повторяемая неделя, не точная история reset.
- Расписание имеет шаг 15 минут. Ручная доля пиковых токенов даёт приближённую пятичасовую оценку.
- Legacy 3× использует старые единицы и не умножается на новые кредиты. Для legacy предусмотрена своя подписка с ручными ценами/покрытием.
- Personal останавливается при исчерпании, если не выбран отдельный PAYG fallback. Он требует Standard API Key и переключения. Coding Plan API Key и Standard API Key имеют разный биллинг с 16.10.2026.
- Team overage и его текущая скидка 10% включаются явно. Срок окончания скидки не опубликован. Пропорциональный перерасход предполагает неизменный mix; порядок запросов может изменить счёт.
- Дополнительные MCP credits вводятся за неделю на человека; весь их дневной объём консервативно помещается в худшие 5 часов. При превышении их неизвестная PAYG-стоимость не объявляется нулевой: результат помечается как неполный.

### OpenAI и Anthropic

- Публичные подписки не гарантируют фиксированную месячную токенную квоту. По умолчанию выводится условный диапазон: seats … seats + полный metered расход. Это не гарантированный потолок счёта. Альтернатива — ввести измеренное покрытие выбранного расхода в процентах.
- Codex paid credits считаются отдельно от API и не имеют отдельного cache-write charge. $0.04 за credit — редактируемое допущение, которое нужно подтвердить в checkout. Included Fast/Ultrafast и paid-credit множители различаются.
- Claude usage bundles — оплаченная покупка: $50 номинала за $45, $250 за $200, $1,000 за $700. Неиспользованные кредиты не считаются возвратом денег. Покупки должны быть целыми; лимиты $2,000 personal/account/month и $3,000 Team/workspace/month.
- Срок переноса bundles **не подтверждён публичным источником**. По умолчанию стоит один месяц без переноса, что даёт консервативный прогноз. Можно указать подтверждённый срок своего аккаунта (1–36 месяцев). Ledger сохраняет остатки до этого срока. Team-позиции одной группы используют общий остаток. Для нескольких personal seats предполагается равномерное распределение покупок/расхода.
- Claude API bonus — отдельный механизм для eligible API/headless: требуется подтверждение claim/7 дней и связи с Console org. Один источник связывается с одним org и наоборот. Team суммарно до $500; personal не умножается автоматически на 10 аккаунтов. Для разных личных источников нужны разные группы и разные связанные org.

### DeepSeek и OpenRouter

- Direct DeepSeek: peak в будни 01–04 и 06–10 UTC, остальное время ×0.5. Китайский праздник можно задать вручную; календарь/перенесённые рабочие дни автоматически не определяются.
- API GLM не получает временную скидку Coding Plan.
- Встроенные DeepSeek маршруты OpenRouter нормализованы к peak/off-peak. Выходной API snapshot мог уже содержать сниженную цену; повторное деление исключено. Альтернативные хосты могут иметь фиксированную цену.
- **Ручные тарифы считаются фиксированными по часам.** Временное уменьшение DeepSeek к ним не применяется. Скорость, контекст и явно введённая геонаценка продолжают действовать. Учитывайте это при вводе уже итоговой цены.
- Standard: inference + 5.5% пополнения, минимум $0.80 за каждое пополнение. Business: 8%, минимум не подтверждён; поле оставлено редактируемым, в модели 0. Предполагается пополнение ровно под остаток расхода, без старого prepaid balance и минимальной суммы principal purchase.
- Несколько Standard/Business позиций означают отдельные бюджеты/пополнения, поэтому минимальная комиссия применяется к каждой. Для одного общего аккаунта используйте одну позицию с несколькими моделями.
- BYOK: внешний провайдер выставляет полный счёт с вашей скидкой; OpenRouter берёт 5% части list-price расхода свыше $25,000/month. Группа аккаунта делит один порог, не по ключу/seat/модели. Другой расход, число пополнений, минимум и Startup должны совпадать во всех BYOK-позициях группы. Сбор распределяется пропорционально расходу; минимум пополнения учитывается один раз на группу.
- OR credits оплачивают inference Standard/Business либо BYOK platform fee, но не внешний provider invoice. Для пополнения под BYOK fee отдельно применяется Standard 5.5% / минимум $0.80 (редактируется).
- Startup только после подтверждённого одобрения: waiver 12 месяцев, введённый остаток гранта до 6 месяцев от одобрения. Не обещаем автоматическую выдачу $3,000.

## Акции, даты и ограничения прогноза

Каталог проверен 17.10.2026, карточки цен GLM и ChatGPT Business — 15.10.2026. Источники и индивидуальные даты указаны в самом HTML. Research snapshots Anthropic/Z.ai/DeepSeek/OpenRouter находятся в `research/`; это исходные данные, не инструкция для приложения.

Annual/quarterly уже содержат скидку периода. Дополнительная скидка не должна повторять её. Разовая акция действует только на первый invoice и только после подтверждения применимости пользователем; с истёкшей датой она выключается. Ночные GLM Flash и другие завершённые акции автоматически не включаются.

Прогноз считает неизменный объём по месячным точкам и последним известным тарифам. Он не предсказывает renewal, новую цену после промо, дневную пропорцию истечения кредитов внутри месяца или изменение токенизации. Разовые пользовательские credits переносятся до явно указанной даты; без даты используются только первый месяц. Monthly credits и API bonus обновляются ежемесячно без накопления.

Налог/надбавка на итог задаётся вручную. Никакие налоги, банковский спред, валютные комиссии, tools/containers/search, SLA или пропускная способность не подразумеваются включёнными. Для дополнительных услуг есть отдельный платёж. Геонаценка вводится явно; regional endpoint может уже включать её. Anthropic US-only +10% не означает Europe. OpenRouter Europe включает EU/EEA, UK и Switzerland, а не строго только ЕС.

Цена не определяет допустимость использования из конкретной страны, KYC или гражданства. Подробности исходного исследования для EU/UK/KZ/RU доступны по ссылке «Полное исследование и KYC» внутри каталога. Общий ключ API не увеличивает лимиты организации и не гарантирует заданное число параллельных coding agents.

## Технические потребители и автоматизация (17.10.2026)

State v3 добавляет `settings.technical`: количество identities, input/output (M на identity/day, включая все workers), дни/месяц, дни/неделю, начало/конец, собственный режим peak и желаемые workers/identity. UTC общий. Начальные 0 identities сохраняют существующие бюджеты; 20M/1M, 30 дней, 7-дневная неделя и 24h — только редактируемый пример. `team` и `profileTotals` считают людей; `technicalTotals` считает машины отдельно. Сводный профиль суммирует оба вида токенов. Цена на разработчика включает выбранный общий бюджет, а для 0 людей не делит на ноль.

`audience=all` означает только разработчиков. `audience=technical` связывает отдельную бюджетную позицию с машинами. Количество процессов не умножает объём, seats или allowance. Расписание через `lineSettings` применяется к token volume, DeepSeek hourly prices, GLM weekly/5h credits. При отключении связи сохраняются effective quantity/volume и `scheduleOverride`; повторная привязка к human-группе убирает override. v1/v2 imports мигрируются в v3 без изменения существующих цен и моделей.

Стоимость и допустимость использования показаны отдельно: `automationAssessment` отмечает supported API, conditional named-user headless, restricted GLM/Claude shared bots и native Codex service account PAYG. Поле «Чьи задачи выполняются» меняет трактовку applicability, не цену. Это оценка соответствия проверенным публичным условиям, не механизм получения лицензии. Подробности и primary links — во вкладке «Автоматизация», источники в `research/technical-*-2026-10-17.md`.

`oai-service` использует метрику Codex credits, no included allowance независимо от старого `coverage`, fixed fee 0 по умолчанию и USD/credit пользователя. Эта позиция не обещает бесплатный workspace и не отождествляется с Platform API. Для собственного договора нужно заменить assumptions. `apiRuntime=claude-action` исключает monthly Claude API bonus даже при выбранном источнике и подтверждении; `own` допускает остальные существующие eligibility проверки.

Учетка сотрудника, используемая headless, учитывается один раз вместе с его ручным расходом. Автоматического связывания разных строк с общим quota pool нет. Разные расписания одного account и bursts требуют измеренного покрытия; техническая группа однородная. Для неоднородных машин можно отвязать позиции в ручной режим. Раннеры/VM добавляются как `extraUsd`. Ключи/секреты в этот калькулятор не вводятся.
